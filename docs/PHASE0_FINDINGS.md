# Phase 0 Findings

Status: **technical gate closed; economic hypothesis open**.

Phase 0 asked whether a small deterministic capability could reproduce a real,
accepted structural change, generalize to a second developer-approved event,
remain idempotent, and refuse incompatible source safely. The retained evidence
lives under [`experiments/phase0/real_capture/`](../experiments/phase0/real_capture/README.md).

## Retained sequence

The sequence is intentionally asymmetric:

1. `seh capability validate` was implemented manually because it created the
   command group and therefore was not a clean recurring event.
2. `seh capability install` started from a recorded clean Git baseline and was
   accepted as ordinary product work.
3. Its recurring structural subset became `add-capability-subcommand`.
4. The capability reproduced `install` byte-for-byte over the declared surface.
5. The `run` wiring was proposed and committed before its behavioral modules
   existed, then approved by the developer and generated by the capability.
6. The retained candidate passed fidelity, generalization, idempotency, and
   safe refusal without adding a primitive merely for experiment coverage.

Using `validate` to judge a candidate derived from `install` is not circular.
The validator is runtime machinery; the candidate is project data being judged.

## Findings that remain normative

### Source preservation

AST nodes locate and validate source spans; textual splice performs the write.
The mutation path never round-trips a module through `ast.unparse()`, because
that would alter comments and formatting outside the declared operation.

### Structural fidelity, not whole-change imitation

Capabilities scaffold recurring structure; they do not author domain behavior.
Fidelity therefore compares only the structural subset explicitly accepted for
capture. Behavioral modules, tests, and command-specific presentation remain
ordinary agent work and are listed as exclusions.

### Capture must preserve the true before-state

A fixture cannot be reconstructed later by subtracting lines from the current
tree. Ordering and surrounding bytes encode history. Every eligible capture
must begin from a recorded clean Git baseline; absent or dirty evidence causes
explicit refusal.

### Repetition means events, not similar structures

Several similar declarations in one snapshot do not prove that a procedure
recurred. They may have been created together. Capability capture is grounded
in accepted change events, with the developer deciding whether the procedure is
worth retaining after the first observed occurrence.

### Selection must follow the roadmap, not the snapshot

Two of the three exploratory capabilities were chosen because `java_adapter.py` held the densest repeated
structure in the tree. That adapter had already been marked frozen; when the project became Python-only it
was removed, and that work — including its primitive-reuse evidence — went with it.

This is the neighbour of the repetition finding above. That one says multiplicity in a snapshot is not
recurrence. This one says structure in a snapshot is not structure the project intends to keep. Capability
selection must be checked against the declared direction, not only against what currently compiles.

The cost was not the deleted code, which was cheap. It was that a documented finding outlived its proof and
had to be withdrawn later rather than never claimed.

### No primitive exists for experiment coverage

The retained capability inserts into existing source. File creation remains
outside the admitted vocabulary until a real recurring event requires it.
Introducing a module solely to exercise a provisional primitive would fabricate
evidence and violate the same honesty rule the gates enforce.

## What is proved

- one prospectively captured capability reproduces its accepted structural
  subset byte-for-byte;
- it generalizes to a developer-approved second event;
- replay is deterministic and content-addressed;
- duplicate application and incompatible anchors refuse safely;
- no model inference occurs in the operation path.

## What is not proved

- broad coverage of project procedure shapes;
- the final public capability schema;
- automated developer-confirmed capture;
- catalogue selection at scale;
- token, latency, authoring-cost, or payback improvement.

The last group is the independent M2 hypothesis. Nothing in Phase 0 should be
quoted as an economic result.
